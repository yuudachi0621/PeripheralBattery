# 外设电量 / PeripheralBattery

Windows 托盘小工具：点一下托盘图标，就能看到 2.4G 鼠标、键盘、蓝牙耳机、手柄的剩余电量。  
界面是 Claude 风格的暖米白面板，常驻后台、几乎不吃 CPU。

## 一、功能

| 需求                | 实现方式                                                   |
| ----------------- | ------------------------------------------------------ |
| 开机自启 + 托盘常驻       | 写 `HKCU\...\Run`（不需要管理员），登录后带 `--tray` 静默启动            |
| 点图标看所有设备电量        | 无边框弹窗贴在工作区右下角，失焦自动收起，Esc 关闭                            |
| 2.4G 鼠标/键盘 + 蓝牙耳机 | 四条独立通道取数（详见第二节）                                       |
| 后续支持 Xbox 手柄      | 已内置：Xbox 手柄在 BLE 下自带 0x180F 电池服务，开机即显示                 |
| 可调轮询频率 + 立即刷新     | 设置里 10s / 30s / 1min / 2min / 5min；点 ↻ 时图标会转一圈作为反馈       |
| CPU / GPU 占用尽可能低  | 事件驱动 + 空闲降频 + 只在档位变化时重绘图标，实测稳态单核 **0.078%**            |
| 自定义设备名称           | 双击设备行**或右键菜单**改名，按设备唯一 ID 记住（换 USB 口也不会丢）              |
| 离线设备折叠            | 「历史设备」折叠区，显示上次电量和"离线 · 3 天前"                           |
| 低电量提醒             | 低于阈值时托盘图标转**红色 + 感叹号角标**，并弹一次 Windows 通知（同次放电只提醒一次）   |
| **托盘图标可读性**       | 16×16 下用**大面积实心色块**（灰壳 + 深色空槽 + 彩色填充），深/浅色任务栏都一眼可辨；读不到电量画"电池 + 横杠" |
| 托盘悬停提示            | **电量前置、竖线分栏、像素级右对齐**，非折叠区设备一台一行全部列出；按电量从低到高排                |
| **指定主设备**         | 只影响托盘图标显示哪个数字，**悬停提示仍列出全部设备**；不选则跟最低值                     |
| **扫描并添加设备**       | 设置 → 扫描其他设备…，四条通道全跑一遍，勾选后加入面板                          |
| **充电状态识别**        | 插线充电时电量旁显示**绿色小闪电**，电量数字仍是真实读数；有线模式的键盘显示「有线 · 充电中」；不触发低电量提醒 |
| **电量未知标识**        | 在线但读不到电量时统一画「电池 + 斜杠」图标（悬停看原因），不画破折号、不画空电量条          |
| **程序图标**           | 陶土橙圆角底 + 白色电池，9 档尺寸（16~256）全部内嵌，任务栏/桌面/资源管理器都清晰           |

> 悬停提示的格式是 **` 41% | GPW 2`**（电量在前、竖线分栏、名字在后）：
>
> ```
>     5% | Enco Free4
>   30% | K600
> 100% | GPW 2
> ```
>
> 中间的 `|` 是**分栏标记**：之前只有空格（` 41%  GPW 2`），提示框是比例字体，
> 数字和名字糊在一起不容易一眼分清，加一条竖线后"竖线右边才是设备名"一目了然。
>
> **为什么电量放前面** —— 这是踩了三个坑之后才定的：
> 1. "名字在前 + 按列数补空格"：截图实测两行差 **25px**，因为提示框是比例字体，
>    空格只有 3px、数字 6px，按"一个字符=一列"补位补不够；
> 2. "名字在前 + 按像素补空格"：对齐准了（两行起点都是 102px），但**补的空格本身就是字符**，
>    3 台设备就 75 字符，直接顶破 Windows 的 63 字符硬上限；
> 3. 电量前置后，各行电量栏长度接近，右对齐要补的空格极少，2 台只要 35 字符。
>
> **但"按字符数补位"仍然对不齐**，这一点又踩了一次：
> Segoe UI 12px 下数字**并不严格等宽** —— 实测 `"  5"`=13.04px、`" 30"`=16.22px、`"100"`=19.41px，
> `PadLeft` 补齐字符数后像素宽度仍差 3~6px。所以最终改用 `TextMetrics.PadToWidth()`，
> **按像素补空格**：先量出这批电量文本里最宽的那个，再给较窄的左侧补空格补到同宽。
> 实测 3 台时三行电量栏终点 32.72 / 32.62 / 32.51px（误差 ≤0.2px），2 台时误差为 0。
>
> 设备名上限 **20 字符**，超出用 `…` 收尾（如 `PRO X SUPERLIGHT 2 …`）。
> 63 字符装不下时（6 台以上），自动压缩排版但**绝不截断设备名**：
> 依次收窄名字 → 电量栏位数 → 分隔符（` | ` → `|`）→ 减少台数并标注 `…等 N 台`。
> 6 台真实设备名压到 62 字符仍全部列出，电量栏终点全部 22.76px。
>
> **充电中的设备**在提示里显示成 `+79%`（数字前一个 ASCII 的 `+`）：
> 提示框总共只有 63 字符预算，写"充电中"要多占 6 个字符，多设备时会把别的设备挤掉。
> 标记用 ASCII 的 `+` 而不是 `⚡` —— 实测 Segoe UI 没有 U+26A1 的字形，
> 提示框里会渲染成一个**空心方框**，比不标还糟。
> 面板里则用真正的矢量闪电图标（`DeviceIcons.Charge`），没有字形问题。
> 读不到电量但正在充电的设备（有线模式的键盘），提示里直接写 `充电中`。

## 二、支持范围（本机实测结论）

先说结论：**能不能读电量，取决于设备本身有没有开放读数接口**，不是软件能凭空算出来的。  
下表的"实测"都是在你这台机器上跑出来的，不是查资料抄的。

| 设备                             | 走的通道                                  | 结果                              |
| ------------------------------ | ------------------------------------- | ------------------------------- |
| 罗技 GPW2（PRO X SUPERLIGHT 2 SE） | 罗技 HID++ 2.0 / Lightspeed 接收器         | ✅ 实测读到 **41%**；插线充电时同样读真值（实测 78%→98% 一路上涨） |
| OPPO Enco Free4                | **OPPO 私有协议**（RFCOMM `0000079A-…A5A5`） | ✅ 实测读到 **左 60% / 右 50% → 显示 50%** |
| Xbox 无线控制器                     | 蓝牙 LE，标准电池服务 0x180F                  | ✅ 手柄开机即读（当前关机所以显示离线）            |
| 机械师 K600（蓝牙 / 2.4G）          | 经典蓝牙 / ITE 接收器 `048D:C102`          | ❌ 电量数字没有（接收器无标准电量用法，见第四节）；如实显示「蓝牙」/「2.4G」 |
| 机械师 K600（有线 / Cable）          | **USB 直连 HID 检测**（按设备名关联）           | ⚡ 显示「有线」+「充电中」（电量数字仍没有）        |

另外，满足下列任一条件的设备都能直接读：

- 任何实现了 HID++ 2.0 的罗技无线设备（罗技自家 Lightspeed / Bolt / Unifying 接收器）；
- 任何暴露了标准蓝牙电池服务 `0x180F` 的 BLE 设备（大部分 BLE 键鼠、部分 TWS 耳机、Xbox Series 手柄）；
- **OPPO / OnePlus / realme 的 TWS 耳机**（BBK 生态共用同一套私有协议，见第四节）。

> K600 的电量**数字**读不到（厂商没开放），第三方工具同样读不到。  
> 但**连接方式**能准确区分：有线模式（拔掉无线、插 USB 线）会在系统里出现一个 USB 直连的
> HID 接口，程序按设备名找到它就显示「有线」+「⚡ 充电中」；纯蓝牙/2.4G 模式则如实显示
> 「蓝牙」/「2.4G」，不会误报充电。

## 三、快速开始

### 直接运行（已发布版本）

```
dist\PeripheralBattery.exe
```

单文件、免安装。首次运行会自动写入开机自启项，之后登录就直接待在托盘里。  
如果只想临时看一眼、不想开机自启，在设置里把「开机自动启动」取消即可。

> 需要 .NET 8 桌面运行时；本机装的是 .NET 10 运行时，已通过 `RollForward=LatestMajor` 兼容，直接能跑。

### 自己编译

```bash
dotnet build -c Release                                  # 编译
dotnet publish -c Release -r win-x64 --self-contained false \
       -p:PublishSingleFile=true -o dist                  # 发布单文件
```

### 使用

- **左键**托盘图标：打开/关闭面板
- **右键**托盘图标：立即刷新 / 设置 / 退出
- **双击**设备行 或 **右键**设备行 →「重命名…」：改名（回车确认，Esc 取消）
- **右键**设备行 →「恢复默认名称」：清掉自定义名称
- **右键**设备行 →「设为主设备」：托盘图标只显示它的电量，面板里标「主设备」
- **右键**设备行 →「取消主设备」：恢复成"所有设备里最低"
- **右键**设备行 →「从面板中移除」：不再显示（可在设置里重新扫描找回）
- **Esc** 或点面板外任意位置：收起面板
- 托盘图标颜色 = 所有在线设备里的**最低电量**（暖绿 >40%、琥珀 15~40%、红 ≤15%、灰 = 无数据）
- 低于低电量阈值（默认 20%）时，图标强制转红并加感叹号角标；
  **正在充电/插着线的设备不算低电量**（插着线还闪红警告纯属添乱），所以这种情况下图标不会变红

> 指定主设备后，这两条会改成"只看主设备"：图标显示主设备的电量，主设备离线时图标变灰（**不会**悄悄退回显示别的设备）。面板标题下会有一行小字写明托盘跟的是谁。
>
> **注意：主设备只影响托盘图标，不影响悬停提示。** 鼠标移上去仍然列出全部在线设备 ——
> 用户悬停的本意就是"一眼看全所有外设"，只报一台反而费解。

设置项：

| 项         | 说明                                        |
| --------- | ----------------------------------------- |
| 刷新间隔      | 10 秒 ~ 5 分钟。蓝牙要唤醒射频，间隔越短越费电；HID 通道几乎免费    |
| 低电量通知     | 弹出 Windows 通知 + 托盘图标转红                    |
| 低电量阈值     | 10% / 15% / 20% / 30%，也是电量条与图标转红的界线        |
| 托盘图标      | 选一台主设备，或「自动」（所有设备最低值）                     |
| 扫描其他设备    | 主动扫一遍四条通道，勾选加入面板                          |
| 开机自动启动    | 写/删 HKCU Run 键                            |
| 显示离线设备    | 关掉后连「历史设备」折叠区也不显示                         |
| 空闲时降低轮询频率 | 用户 5 分钟无操作后，只跑 1/4 的轮询次数                  |

## 四、设备实测记录

### OPPO Enco Free4：是怎么把电量读出来的

这台耳机一开始是"读不到"的典型，排查过程值得留档，因为结论有点反直觉：

```
经典蓝牙：已连接（A2DP）；ClassOfDevice = 0x240404 (AudioVideo)
BLE 侧 ：FromBluetoothAddressAsync 直接超时 —— 设备根本不广播 LE
系统层 ：Get-PnpDeviceProperty 里没有 DEVPKEY_Device_BatteryLevel
         （Windows 设置页对这副耳机也不显示电量）
HFP    ：RFCOMM 通道 0000111E 存在，但连接被拒（音频正被系统占用）
```

三条常规路全断，但它其实在 SDP 记录里公开了第三个通道：

```
0000079A-D102-11E1-9B23-00025B00A5A5   ← OPPO/OnePlus/realme 共用的私有控制通道
```

连上之后发一条只读查询就能拿到电量：

```
发：AA 07 00 00 06 01 05 00 00          （Cmd=0x0106，电量查询）
收：AA 0B 00 00 06 81 05 04 00 00 02 01 3C 02 32
                                      └─ 0x8106，载荷 00 02 01 3C 02 32
```

载荷 `状态(1) + count(1) + (part, raw) × count`：

| 字段    | 含义                                              |
| ----- | ----------------------------------------------- |
| part  | `01` 左耳 / `02` 右耳 / `03` 充电盒                    |
| raw   | `raw & 0x7F` = 百分比，`raw & 0x80` = 正在充电          |
| 本例    | `01 3C` → 左耳 60%；`02 32` → 右耳 50%               |

显示时取左右耳的**较低值**（低的那个才是真续航），并注明"左右耳取最低"。

### 罗技 HID++ 0x1004：怎么判断"在充电"还是"USB 直接供电"

特性 `0x1004` UNIFIED_BATTERY 的 `fn1 getStatus` 应答里有两个容易混淆的字节：

| 偏移 | 含义 | 取值 |
| --- | --- | --- |
| `[4]` | 电量百分比 | 0~100 |
| `[5]` | 原始档位 | 厂商自定，一般不直接用 |
| `[6]` | 充电状态 | `1`=充电中、`2`=已充满、`0`=未充电 |
| `[7]` | **外部供电状态** | `0`=靠电池、`1`=接了 USB 线、`2`=有线模式下已充满 |

两者不是一回事：**插着线但电池已经满了**的时候，`[6]` 会回到 `0`（不再充），
`[7]` 仍然是 `1`/`2` —— 这正是"外设直接由 USB 供电"的情形。

所以程序对 `[7] != 0` 的设备在电量旁加一个**绿色小闪电**，副标题写「USB 供电」，
但**电量数字照实显示**（实测插线时读到 79%，充电中还在往上走）。
早先的版本在这里一律显示「充电中 100%」，用户看到 100% 而实际 79% 会以为程序读数不准，已改掉。
这类设备**不参与低电量判断**（插着线还弹"电量低"是最糟糕的体验），
托盘图标取值也走真实读数，不会出现"面板写 100%、托盘却是红的 12%"。

### 机械师 K600 的 2.4G 接收器

枚举出来的 HID 接口是 `VID_048D&PID_C102`（ITE 芯片），它的四个集合分别是：

```
FF89/0010  (厂商自定义，无输入输出报告，只有 Feature Report)
000C/0001  (消费类控制)
0001/000C  (厂商自定义)
000C/0001  (消费类控制)
```

三个事实说明它没有标准电量通道：

1. 报告描述符里**没有** HID 标准电量用法（UsagePage `0x06` / Usage `0x20` Battery Strength）；
2. 没有任何 BLE 侧服务（它不是双模设备）；
3. 键盘本身也不是罗技设备，没有 HID++ 协议。

电量只存在于厂商私有 Feature Report 里。`--probe` 会对这个接口全量扫 Feature Report
（reportId 0x00~0xFF），实测只有 `0x5A` 有响应、且在键盘不通过 2.4G 连接时返回全 `FF`
（= 无数据）。要拿到数字需要逆向 Machenike 驱动的协议，属于"可以做但不通用"的范围。

### 机械师 K600：连接方式怎么判（已实现，踩过一次坑）

电量数字拿不到，但**有线/无线是能准确区分的**。判据只有一条：
**USB 里有没有这台设备的直连接口**（路径形如 `hid#vid_xxxx&pid_xxxx`，
蓝牙 HID 的路径则带 `{00001124-…}` 服务 GUID）。

- 有线模式：USB 里出现 `VID_05AC&PID_024F`、产品名与设备名一致的接口
  → 拉回在线、连接方式设为**有线**、显示「⚡ 充电中」；
- 蓝牙/2.4G 模式：USB 里没有它 → 如实显示「蓝牙」/「2.4G」，**不报充电**；
- 拔线/切回无线后，上一轮的有线标记自动清除、连接方式还原。

关联靠**设备名**：USB HID 拿不到蓝牙地址，所以比对 `CustomName` 或 `DefaultName`
（实测该键盘 USB 侧的产品名就是 `Machenike K600`，改名后也可能变成你设的名字）。
两种名字都不匹配时认不出来，代价是那台键盘显示为离线 —— 但不匹配总比误判成"在充电"强。

⚠️ **踩坑记录：千万不要用 PnP 属性判断充电状态。**
`--probe-setup K600` 能看到这个属性组：

```
BTHENUM\DEV_A1B2C3D4E5F6\…          ← 地址为示例，实际是你那台键盘的蓝牙 MAC
    BatteryLevel         (pid=2)  FILETIME 全零 → 没有电量数字
    BatteryChargingState (pid=4)  BOOLEAN True  → ⚠️ 拔了线、纯蓝牙时同样是 True
```

`pid=4` 语义上像"充电中"，但**恒为真、与物理插线无关**。早先版本拿它推断"USB 供电"，
结果用户拔掉线用蓝牙，面板还一直写「USB 供电 · 充电中」，被反馈纠正后已移除该推断。
`Native/PnpBattery.cs` 现在只读 `pid=2`（且要求是 BYTE 型）拿电量百分比，不碰充电状态。

### 读不到电量时显示什么

统一显示一个**"电池 + 斜杠"**图标（`DeviceIcons.Unknown`，描边、次要色），不再画破折号：

- 破折号在比例字体里跟对齐补白混在一起，容易被看成"少打了个字"或者直接忽略；
- 图标至少能说明"这台设备在线、但读不到电量"，悬停还能看到原因（如"未提供电量接口"）；
- 电量条同时隐藏 —— 画个空槽会被读成 0%。

### 托盘图标为什么长这样

Windows 只给托盘 16×16 像素，能表达的信息极少。这一版是返工两次后的结果：

| 做法 | 结果 |
| --- | --- |
| 细描边轮廓 + 内部填充 | 缩到 16px 后轮廓只剩 1px，在深色任务栏上糊成一条灰边；低电量时填充区几乎看不见 |
| 半透明灰外壳 | 深色任务栏上几乎不可见（和背景融成一片） |
| **三层不透明色块**（当前） | 中灰外壳 + 深灰空槽 + 彩色填充，深色/浅色任务栏都清晰；电池占满画布 |

另外几个刻意的细节：

- 未填充区用**深灰空槽**而不是留白：留白会被读成"0%"，空槽才能表达"这块是空的"；
- 读不到电量画"电池 + 一道横杠"，不是空槽（空槽 = 快没电了，语义完全不同）；
- 低电量角标 13px（16px 下约 6.5px），感叹号用**几何矩形**画 —— 字体在这个尺寸下
  hinting 会糊成一团；
- 电量按 **5% 分档**缓存，只有跨档才重画（16px 上 1% 的差别根本看不出来，还费 GDI 句柄）。

`--ui-shot` 会顺带在同一目录生成 `ui_tray.png`：**深色/浅色两行**、每档电量一格，
而且是先缩到真实 16px 再放大 4 倍 —— 直接放大 32px 原图会掩盖"缩到 16 之后糊不糊"这类问题。

### 四条通道是怎么合并的

每个通道返回 `ProviderResult { Ok, Devices[] }`，合并规则有这几条关键点：

1. **HID 先跑、蓝牙后并行**。  
   实测罗技接收器和蓝牙密集建链会互相拖累：启用 OPPO 通道后罗技从 2 秒变 9.4 秒且读不到设备，
   禁用后立刻恢复 2 秒 / 100% 读到。所以让 HID 通道独占先跑完，再放三条蓝牙类通道并行。
2. **只有"这一轮通道成功"时，才允许判定它名下的设备离线**。  
   蓝牙服务偶尔抽风会整条失败，这时候不能把用户所有蓝牙设备都标成离线。
3. **连续两轮读不到才判离线**，而且启动时先沿用上次的在线状态。  
   无线设备从省电状态唤醒时偶尔会漏掉请求，只漏一次就标灰会让面板乱闪。
4. **空手而归就补一轮**：通道本身正常却一台都没读到，3 秒后自动再试一次。  
   实测罗技接收器"刚被打开"时的首个请求经常被吞掉，紧接着的第二次访问基本都能成功。
5. **同一台设备可能被多条通道同时看到**（Enco Free4 既有经典蓝牙条目又有 OPPO 协议条目），  
   所以设备 ID 统一：BLE / 经典蓝牙 / OPPO 都用 `bt:{MAC}`（12 位十六进制），
   罗技用 `logi:{unitId:X8}`（HID++ 的 Device Information 特性给的 8 位十六进制序列号；
   读不到 unitId 时退回用设备名当 Id，换 USB 口也认得）。  
   合并时按 `_providers` 数组顺序逐个 Upsert，**后写覆盖前写** —— 所以 OPPO 通道排在最后，
   它读到的真实百分比会盖掉经典蓝牙那份"没有电量"的空快照。

### 低电量提醒为什么不会刷屏

轮询每分钟一次，如果无条件弹气泡，一晚上能弹几十次。`LowBatteryWatcher` 用这几条规则解决：

1. **同一次放电只提醒一次** —— 记住该设备已经提醒过；
2. **正在充电 / 插着线的设备根本不提醒** —— 插着线还弹"电量低"是最糟糕的体验；
3. **清记忆的条件**：充上电、或电量回升到 **阈值 +5 以上**（5% 迟滞，防在阈值附近反复横跳）。
   "重新连接"本身不清记忆 —— 否则摘下来再戴回去就会再弹一次；
4. **6 小时冷却期** —— 防电量在阈值上下反复横跳。

另外一轮里有多台同时低电量时，只报电量最低的那一台。

### 为什么"扫描"和"轮询"是两件事

轮询会看到周围所有外设：同事的耳机、配对过但不用的设备、手机……全塞进面板就是噪音。
所以这里把**发现**和**关注**拆开了：

| 概念 | 由谁负责 | 落盘在哪 |
| --- | --- | --- |
| 发现（这台设备存在、现在是多少电） | 四条通道的 `PollAsync` | 不落盘，每轮重算 |
| 关注（要不要显示在面板里） | `DeviceRecord.Tracked` | `config.json` |

具体规则：

- **常规轮询只处理 `Tracked = true` 的设备**。通道就算读到了别的设备，`Merge` 里直接跳过，不会自动加进面板。
- **用户点"扫描其他设备"才会看到全部**。`ScanAsync` 绕过 Tracked 过滤，所以之前删掉的设备还能被重新找回来。
- **老配置兼容**：`Tracked` 布尔字段缺省是 `true`，升级后原有设备一个不丢。
- **`Remember()` 必须保留 `Tracked`**，否则每次落盘都会把它写成 `true`，删掉的设备下一轮就自己回来了 —— 这个坑很容易踩。
- **移除分两种情况**：设备在线时只置 `Tracked = false`（还能扫回来，自定义名称也留着）；已离线时连记录一起删（免得配置里攒垃圾）。

主设备的实现也有一处要注意：`TrayPercent()` 在主设备离线时返回 `null`（图标画灰色），
**不能**退回"所有设备最低值" —— 否则用户会看到别的设备的电量却以为是自己那台的。

## 六、低功耗是怎么做到的

| 手段                                        | 效果                          |
| ----------------------------------------- | --------------------------- |
| `System.Threading.Timer` 到点才醒，面板关闭时零渲染    | 无轮询动画、无定时刷新 UI              |
| 只查"当前已连接"的蓝牙设备（AQS 过滤）                    | 一轮从 13 秒降到 2 秒，且不再为关机设备空等超时 |
| 空闲 5 分钟降到 1/4 频率                          | 人不在电脑前时几乎完全不活动              |
| 托盘图标只在电量档位（5% 一档）+ 低电量状态变化时重画           | 不产生 GDI 句柄与重绘开销             |
| BLE / OPPO 通道读完立刻断开连接                     | 不常驻占用射频链路                   |
| 面板用无边框 + DWM 圆角（不开启 `AllowsTransparency`） | 窗口仍是硬件加速，不退化到软件渲染           |
| HID 通道用 20 字节报文一问一答                       | 单次 < 1ms，USB 几乎无感           |

实测（Debug 版，60 秒稳定态采样，20 线程 CPU）：

```

工作集            : 69 MB（含 .NET 运行时）
私有内存          : 15 MB
线程 / 句柄       : 23 / 546
一轮轮询耗时      : 约 2~4 秒（罗技 2 秒 + 蓝牙类并行 1.5~2 秒）
```

## 七、排查问题

```bash
# 1. 看设备真相：HID 接口、HID++ 握手、蓝牙服务、电量原始字节
#    以及对 048D 键盘接收器做 Feature Report 全量扫描（reportId 0x00~0xFF）
PeripheralBattery.exe --probe                 # → %TEMP%\pb_probe.txt

# 2. 某副蓝牙耳机读不到电量？按顺序试这几条
PeripheralBattery.exe --probe-headset Enco    # BLE 全量服务 + 强连 + 系统层缓存
PeripheralBattery.exe --probe-hfp Enco        # HFP 的 AT 指令（IPHONEACCEV）
PeripheralBattery.exe --probe-opo Enco        # OPPO/OnePlus/realme 私有协议
PeripheralBattery.exe --probe-setup           # 直读 PnP 属性，看系统有没有缓存电量

# 3. 逻辑自检（低电量判定、主设备、移除后不复现、悬停提示是否列全、电量是否对齐、充电状态显示等 117 项断言）
PeripheralBattery.exe --selftest              # → %TEMP%\pb_selftest.txt

# 4. 看运行日志（通道失败、慢通道、异常）
%APPDATA%\PeripheralBattery\app.log

# 5. 看/改配置（设备名、间隔、阈值、历史）
%APPDATA%\PeripheralBattery\config.json

# 6. 改版式时把界面渲染成图（不弹窗）
PeripheralBattery.exe --ui-shot D:\tmp\ui.png          # 真实数据的面板
PeripheralBattery.exe --ui-shot D:\tmp\ui.png demo     # 造几台假设备，看各种状态
PeripheralBattery.exe --ui-shot D:\tmp\ui.png settings # 设置窗口
PeripheralBattery.exe --ui-shot D:\tmp\ui.png scan     # 扫描窗口（会真的跑一遍四条通道）
```

> `--ui-shot` 每次都会往日志写一行**布局体检**结果（"无溢出"或具体哪几个元素超出可用宽度）。
> 界面上"文字被裁一半"光看截图容易漏，看这个数字最直接。

> **所有诊断模式都不写配置**（`ConfigStore.ReadOnly`）。它们会构造 `BatteryMonitor` 并调用
> `SetPrimary` / `Remove` 这类内部带 `SaveNow()` 的方法，若不拦截，跑一次 `--selftest`
> 就会把真实的设备名、主设备设置覆盖成测试数据。开发时新增诊断入口请记得沿用这个开关。

常见情况：

- **鼠标电量一直读不到** → `--probe` 里看 `idx=0x01 在线` 那一段有没有 `特性 0x1004`；没有就该型号不支持。
- **刚启动时罗技设备显示"离线 · 刚刚"** → 无线设备在省电状态时首个请求容易被吞。程序会自动 3 秒后补一轮，  
  连续两轮读不到才会真的标离线；点一下「立即刷新」也能立刻恢复。这是硬件唤醒特性的限制，不是程序卡住。
- **耳机电量比其他软件显示的高/低** → OPPO 通道取的是左右耳里的较低值；手机 App 可能显示平均值。
- **托盘图标是灰的** → 说明一台设备都没读到电量，看日志里哪条通道失败。
- **设备不出现在面板里了** → 可能是被"从面板中移除"过。到 设置 → 扫描其他设备… 重新勾选即可找回（自定义名称和主设备设置都还在）。
- **托盘图标一直显示某一块** → 你在右键菜单里设了主设备，面板标题下会写"托盘图标：XXX"。改成「取消主设备」就恢复"所有设备最低"。
- **面板一闪就没了** → 点托盘图标时如果焦点被别的置顶窗口抢走，会触发"失焦收起"；  
  程序里已经对弹出后 250ms 内的失焦做了忽略，若仍复现请贴日志。

## 八、想加新设备怎么办

实现一个 `IBatteryProvider` 就行，不用动 UI：

```csharp
public sealed class MyProvider : IBatteryProvider
{
    public string Name => "我的设备";
    public Task<ProviderResult> PollAsync(CancellationToken ct)
        => Task.FromResult(new ProviderResult
        {
            Ok = true,
            Devices = { new DeviceSnapshot { Id = "my:1", Name = "XX 键盘", Percent = 77 } }
        });
}
```

然后在 `BatteryMonitor` 构造函数里加进 `_providers` 数组。
注意：如果它走蓝牙类链路（RFCOMM / GATT），要和蓝牙通道放在同一组并行；
如果走 USB HID，就要放进 HID 那组先跑（原因见第五节第 1 条）。

两个已经预留好的方向：

- **XBOX 有线 / 官方无线适配器**：这两条路走的是微软 GIP 协议（USB 上发 `0x07` 命令取电量），  
  需要额外实现一个走 USB 而非 BLE 的 Provider。BLE 模式现在已经能用。
- **其他品牌 TWS 耳机**：先跑 `--probe-hfp` 看它认不认 `AT+IPHONEACCEV`（很多非苹果耳机为了兼容 iPhone 会认），  
  再跑 `--probe-headset` 看 SDP 里有没有厂商私有通道。找到了就照 `OpoProvider` 的样子再加一条。
