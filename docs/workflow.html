02一轮轮询的数据流

① 罗技 2.4G 通道（先跑）
1SetupAPI 枚举 HID 接口
2筛出 VID_046D 且 UsagePage=0xFF00、报文 20 字节的接口
3扫设备索引 0xFF、1~6，用 HID++ 2.0 Ping 探活
4读 0x0005 名称、0x0002 序列号
5读 0x1004 统一电量（含充电状态）
GPW2 → 41%
② OPPO 耳机通道（并行）
1AQS 取「已连接」的经典蓝牙设备
2查 RFCOMM 服务 0000079A-D102-…A5A5（BBK 系私有控制通道）
3连上后发 0x0106，收 0x8106
4解析 (part, raw)：01 左耳 / 02 右耳 / 03 盒，bit7 = 充电
Enco Free4 → 左 60% / 右 50% → 取 50%
③ 蓝牙 LE 通道（并行）
1AQS 只取「已连接」的 BLE 设备（关机设备不再空等超时）
2按 UUID 单查电池服务 0x180F，不做全量服务发现
3读电量特征 0x2A19；多实例取最小值
4读完立刻释放连接，不长期占用射频
Xbox 手柄 → 读 0x2A19
④ 经典蓝牙通道（并行）
1AQS 直接筛「已连接」的经典蓝牙设备
2取名称与地址，按名字猜设备类型
3拿不到电量时，只报在线状态与原因
4不认识的设备类型直接跳过，不刷屏
与 ② 同 ID 时，去重后保留有电量的那条
↓  四条通道都产出 DeviceSnapshot  ↓
合并（BatteryMonitor.Merge，在 UI 线程执行）
  • 统一设备 ID：BLE / 经典蓝牙 / OPPO 都用 bt:{MAC}，罗技用 logi:{序列号}（无序列号则用型号名）——同一台设备被多条通道看到也不会重复显示。
  • HID 先跑、蓝牙后并行：实测罗技接收器和蓝牙密集建链会互相拖累（对照实验：启用 OPPO 通道后罗技从 2 秒变 9.4 秒且读不到设备），所以让 HID 独占跑完再放蓝牙。
  • 只有通道成功时才能判离线：蓝牙服务整条失败时保留上次状态，不会把设备全标灰。
  • 连续两轮读不到才判离线：无线设备偶发不应答不会让界面闪烁；启动时先沿用上次的在线状态。
  • 空手而归就补一轮：某条通道这轮一台都没读到，3 秒后自动再试一次（罗技接收器首次请求常被吞掉，第二次基本都能成）。
  • 有百分比覆盖空值：同一 ID 先收到"未提供电量接口"、后收到真实电量时，电量与说明都会被正确更新。
  • 少抖动：集合只做增删与位移，不整表重建，面板不会闪。

03协议关键点（实测得出）

关键点说明
0x11 报告HID++ 2.0 长报文：[0x11, 设备索引, 特性索引, 函数<<4|swId, 参数…]，共 20 字节。
0xFF 索引表示接收器自身。本机 Lightspeed 接收器不响应 HID++，真正的鼠标在索引 0x01。
0x1004UNIFIED_BATTERY。func1 返回 [电量%, 原始档位, 充电状态, 外部供电]，GPW2 只支持这个，不支持 0x1000 / 0x1001。
0x180F / 0x2A19蓝牙标准电池服务与电量特征，Xbox 手柄、多数 BLE 键鼠与部分 TWS 耳机都提供。
0000079A-…A5A5OPPO / OnePlus / realme 耳机共用的私有控制通道（RFCOMM，非 BLE）。Windows 设置页对这类耳机不显示电量，系统也没缓存 DEVPKEY_Device_BatteryLevel。
AA | Len | Cmd | SeqOPO 帧格式：AA 开头，长度用 LEB128 编码，之后是 00 00 + 命令(2 字节小端) + Seq(1) + 载荷长度(2) + 载荷。回复命令号 = 请求命令号 | 0x8000。
0x0106 → 0x8106电量查询。载荷 = 状态(1) + count(1) + (part, raw) × count；part 01 左耳 / 02 右耳 / 03 盒，raw 的 bit7 = 充电，低 7 位 = 百分比。实测回包：00 02 01 3C 02 32 → 左 60% / 右 50%。
AQS 已连接过滤用"只查已连接设备"的选择器，一轮轮询从 13 秒降到 2 秒，也不再为关机设备白等超时。
读不到电量的设备怎么办？ 界面上显示"在线 · 未提供电量接口"，而不是猜一个数字。
机械师 K600 的 ITE 接收器（048D:C102）报告描述符里没有 HID 标准电量用法，也不支持 BLE； OPPO 的私有协议只有 BBK 系（OPPO / OnePlus / realme）耳机才认，其它品牌走不通这两条。README 第四节有完整实测记录。

04低功耗都省在哪

手段效果
System.Threading.Timer到点才唤醒，关着面板时不做任何渲染。
空闲降频用户 5 分钟无输入时只跑 1/4 次数（蓝牙射频唤醒是主要成本）。
图标按档位缓存只在电量档位或低电量状态变化时重画，其余时候复用同一个 GDI 图标。
读完即断开BLE / OPPO 通道读完立刻释放连接，不常驻占用射频链路。
实测占用稳态 0.078% 单核、工作集 69 MB、私有内存 15 MB（40 秒 / 60 秒两段采样）。
